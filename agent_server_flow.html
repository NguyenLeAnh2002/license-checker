Communication Protocol: HTTP/HTTPS with JSON payload. Agent sends license detection results every 5 minutes to server endpoint.

🔄 5-Minute Detection Cycle

T+0s
🎯 Trigger Detection
Background worker wakes up every 5 minutes
T+1-3s
🔍 Detect License
Tier 1: SL APIs → Tier 2: WMI → Tier 3: Registry
Result: LicenseStatus enum + metadata
T+3-4s
📝 Prepare Report
Collect machine info (hostname, OS version)
Serialize to JSON with timestamp
T+4-5s
📤 Send to Server
HTTP POST /api/agent/report-license
Retry max 3 times if fails
T+5s
✅ Server Receives
Validate API key
Parse JSON
Update database
T+5.1s
🎉 Done
Response: 200 OK
Dashboard refreshes within 30 seconds

📡 HTTP Request Details

1 Endpoint: POST /api/agent/report-license
2 Authentication: X-API-Key: {api-key-from-dashboard}
3 Content Type: application/json

Request Example:

POST /api/agent/report-license HTTP/1.1 Host: server-ip:8000 X-API-Key: agent-key-12345 Content-Type: application/json Content-Length: 256 { "hostname": "DESKTOP-ABC123", "department": "Finance", "os_version": 10, "os_edition": "Pro", "licenseStatus": "Legitimate", "windowsEdition": "Pro", "kmsStatus": "KMSDetected", "windowsKmsServer": "kms.corp.local", "timestamp": "2026-08-06T19:00:00Z" }

Response Example (200 OK):

HTTP/1.1 200 OK Content-Type: application/json { "status": "received", "machine_id": 42, "timestamp": "2026-08-06T19:00:00Z" }

📝 JSON Payload Structure

Field Type Example Description
hostname string "DESKTOP-ABC123" Machine name from GetComputerName()
department string "Finance" Department/organizational unit
os_version integer 10 7, 8, 10, 11, or 2008, 2012, 2016, 2019, 2022
os_edition string "Pro" Pro, Enterprise, Home, Server edition
licenseStatus enum "Legitimate" Legitimate | Cracked | NotLicensed | UnableToDetermine
windowsEdition string "Pro" Windows edition name
kmsStatus enum "KMSDetected" NotKMS | KMSDetected | KMSNotFound | Error
windowsKmsServer string "kms.corp.local" KMS server hostname/IP (if using KMS)
officeStatus enum "Legitimate" Office license status (optional)
officeKmsServer string "kms.corp.local" Office KMS server (if different)
isError boolean false true if detection encountered error
errorMessage string "API unavailable" Error details (if isError = true)
timestamp string "2026-08-06T19:00:00Z" ISO 8601 detection timestamp

🖥️ Machine Identification

How Server Identifies Machines:
Server uses hostname as unique identifier. If hostname matches existing machine → update. Otherwise → create new record.

Getting Machine Info (C++):

// Get hostname char hostname[MAX_COMPUTERNAME_LENGTH + 1]; DWORD size = sizeof(hostname); GetComputerNameA(hostname, &size); // Get Windows version DWORD version = GetWindowsVersion(); // Returns 7, 8, 10, 11 // Get Windows edition std::string edition = GetWindowsEdition(); // "Pro", "Enterprise" // Get KMS server (from registry) std::string kmsServer = GetKMSServer(); // "kms.corp.local"

Server-side Processing:

1. Receive JSON with hostname="DESKTOP-ABC123" 2. Query: SELECT * FROM machines WHERE hostname='DESKTOP-ABC123' 3. If found → UPDATE licenses table with new status 4. If not found → INSERT new machine, then INSERT license 5. Archive old license to license_history 6. Return machine_id in response

🔐 Authentication (API Keys)

How to Generate API Key:
1. Open Dashboard: http://localhost:8000/dashboard
2. Login: admin / admin123
3. Settings tab → "Generate New Key"
4. Copy key and deploy to agent machines

Using API Key in Request:

// curl example curl -X POST http://server:8000/api/agent/report-license \ -H "X-API-Key: YOUR-KEY-HERE" \ -H "Content-Type: application/json" \ -d '{...}' // C++ example curl_easy_setopt(curl, CURLOPT_HTTPHEADER, headers); headers = curl_slist_append(headers, "X-API-Key: YOUR-KEY-HERE");

✅ Valid Request

  • X-API-Key header present
  • Key matches active key in dashboard
  • Valid JSON in body
  • Response: 200 OK

❌ Invalid Request

  • No X-API-Key header
  • Key is inactive/revoked
  • Invalid JSON format
  • Response: 401 Unauthorized

⚠️ Error Handling & Retry Logic

Status Code Meaning Agent Action
200 OK - Report received ✅ Success, log and continue
400 Bad Request ❌ Invalid JSON, don't retry
401 Unauthorized ❌ Invalid API key, don't retry
500 Server Error ⏳ Retry (max 3 times with delay)
Timeout Network timeout ⏳ Retry (max 3 times with delay)

Retry Strategy:

Max Retries: 3 Retry Delay: 60 seconds Attempt 1: Send report → Success? Return Attempt 2: Wait 60s → Send report → Success? Return Attempt 3: Wait 60s → Send report → Success? Return Failed: Log error, wait until next 5-minute cycle
Important: Only retry on network/server errors (5xx, timeouts). Do NOT retry on 400/401 errors.

🔧 Troubleshooting

❓ Server not receiving reports

Check:
1. Server running? → curl http://localhost:8000/api/health
2. API key correct? → Compare dashboard key with agent config
3. Network connectivity? → ping server from agent machine
4. Firewall? → Allow port 8000
5. Agent logs? → Check C:\Program Files\LicenseChecker\license-detection.log

❓ Dashboard shows no machines

Check:
1. Agent sending reports? → Check agent logs
2. Server receiving? → Check server logs (watch FastAPI output)
3. Database? → sqlite3 license_checker.db "SELECT COUNT(*) FROM machines;"
4. Refresh? → Press F5 on dashboard, check browser cache

❓ 401 Unauthorized errors

Check:
1. API key in config? → Should match X-API-Key header
2. Key active in dashboard? → Check Settings tab
3. Key format? → No spaces or special characters
4. Header format? → X-API-Key: key-value (not Bearer token)
